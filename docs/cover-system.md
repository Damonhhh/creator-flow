# 通用封面交付协议

封面是独立的点击资产，不等于视频第一帧。它只负责让目标观众在缩略图里迅速看懂“这条内容讲什么、为什么值得点开”。账号专属配色、字体、栏目符号和固定视觉资产，应由使用者在自己的项目中定义。

## 默认交付

- 竖版主封面：`1080x1920`（9:16），用于竖屏信息流。
- 横版适配封面：优先原生 `4:3`，用于横版发布、平台裁切和合集同步。
- 需要 B 站或 YouTube 时，另做 `1920x1080`（16:9）版本。

除非发布范围明确只有一个平台，正式发布包默认同时包含竖版与横版封面。两者可以共享视觉概念，但必须分别构图，不能互相硬裁。

## 构图与文字

- 只保留一个清楚的主视觉，缩小到手机信息流尺寸后仍能识别。
- 主标题通常 2—3 行，每行约 4—7 个汉字，最多 3 行；标题本身要包含主题对象。
- 副标题不是默认项；需要时只写一句短句。角标最多一个。
- 竖版标题放在上半区的安全位置，横版通常采用左侧文字、右侧主视觉；所有关键信息都要远离裁切边缘。
- 中文由本地排版完成。生成式图片只负责底图、主体、光线和氛围，不能依赖模型生成可读中文。
- 不用长段解释文字，不把封面做成 PPT 标题页、知识卡截图或临时信息面板。

## 发布前 QA

- 实际打开竖版和横版文件目检，确认尺寸、方向和文件完整。
- 在手机缩略图大小检查：标题可读、主体可认、画面和标题表达同一个问题。
- 检查标题、核心卖点和必要声明都处于安全区。
- 在 `4:3` 中心预览里确认横版标题与主体不会丢失。
- `16:9` 版本必须重新构图，不能由竖版硬裁。
- 若主视觉混乱、文字不可读或任一版本缺失，先返工，不进入发布同步。

这个协议只规定公共门槛。具体颜色、字体、版式模板和账号识别系统属于使用者自己的风格资产。
