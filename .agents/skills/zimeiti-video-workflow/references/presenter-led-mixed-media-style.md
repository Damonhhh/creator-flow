# 数字主持·素材接管式主风格

## 定位

`presenter-led-mixed-media-v1` 是本账号 AI、商业解说和案例拆解的默认成片风格。其外部正例来源已核验为所长林超 2026-05-01 发布的《超指数分化世界》（作品 ID `7634861116409138466`，核验文件时长约 13:53、1920×1080）；目前没有证据支持把其他账号并列写成这套规则的来源。该风格只提取参考片中可迁移的成片逻辑，不复制字体、棚景、青色边框、科技底纹、包装或具体转场。

一句话定义：

> 由会说话的人物带领叙事，官方证据、产品 Demo、真实素材、图片动效和必要的 AIGC 场景轮流接管主画面；人物回来解释意义和给出判断，而不是站在 PPT 旁边从头讲到尾。

这里的 PERSON 可以是真人，也可以是数字人。本账号默认用通过口型和人工复核的动态数字人替代真人主持。静态人物照片、循环呼吸图或不会说话的母图不能冒充人物出镜。

本合同负责“用什么媒介完成画面职责”；`screen-owner-v1` 仍是唯一负责“当前由谁拥有叙事权”的通用合同，两者不得重复或冲突。

## 五种主画面媒介

| `presentation_mode` | 用途 | 正常来源 | 画面要求 |
| --- | --- | --- | --- |
| `avatar-talk` / `live-presenter` | 提问、判断、转折、章节开启、情绪抬升、结论 | 已验收动态数字人 / 真人实拍 | 人物全屏或占据明确主画面，嘴型与声音成立 |
| `official-proof` / `product-demo` | 数字、引用、官方声明、功能与操作证明 | 一手页面、官方视频、真实录屏 | 能独立读懂，必要时局部放大、高亮或跟随操作 |
| `real-footage` | 工作流、生产、企业应用、真实行为与后果 | 实拍、新闻现场、授权 B-roll | 看得到真实主体在做什么，不能只当氛围壁纸 |
| `kinetic-image` | 把有价值的静态图片变成镜头 | 官方图片、摄影、生成静帧 | 全画面或主画面使用；推拉、景深、遮罩、局部揭示必须服务叙事动作 |
| `aigc-scene` / `explainer-animation` | 拍不到的未来状态、不可见机制、空间关系和转场 | 明确标注的生成素材 / 本地动画 | 只负责解释、演绎或桥接，不承担事实证明 |

`support-card` 只是一种短桥接，不是主风格。它可用于一句定义、一个必要清单或章节提示，但不得连续成为视频骨架，也不能靠飞入、数字放大和箭头绘制伪装成镜头推进。

`support-card` 按实际叙事职责判断，不按截图或切点机械计数。同一张解释图在一个连续任务里逐步揭示、缩放、高亮和改变关系，仍是一个持续演进的 `official-proof`、`kinetic-image` 或 `explainer-animation`；只有多个彼此独立、主要靠标题和容器替换承载口播的板式画面，才构成连续卡片。

## 素材选择顺序

在同一句话有多个可行方案时，按职责选择，而不是机械按等级替换：

1. 要证明：优先一手官方材料、真实 Demo、真实录屏。
2. 要落到现实：优先实拍、生产现场、办公动作、用户行为。
3. 有好静帧但缺视频：用 `kinetic-image` 做成真正的镜头，不排成信息卡。
4. 要解释看不见的机制或展示无法拍摄的状态：使用 `aigc-scene` 或 `explainer-animation`。
5. 上述媒介都不能更清楚地完成任务时，才短暂使用 `support-card`。

AIGC 是补充镜头，不是默认填充物。现实中已有可获得的官方证明、真实操作或真实现场时，不要生成一个更漂亮但更假的替代品。

## 与屏幕所有权的映射

| Owner | 优先 `presentation_mode` | 不允许的偷懒方式 |
| --- | --- | --- |
| `PERSON` | `avatar-talk`、`live-presenter` | 静态头像、角落贴纸、人物与 PPT 长期并排 |
| `EVIDENCE` | `official-proof`、`product-demo` | AIGC 截图、无来源动画、把结论写在卡上冒充证明 |
| `EXPLAINER` | `product-demo`、`kinetic-image`、`aigc-scene`、`explainer-animation` | 抽象图标堆叠、只有名词没有动作、连续知识卡 |
| `SCENE` | `real-footage`，必要时 `kinetic-image` 或明确标注的 `aigc-scene` | 与口播无关的氛围空镜、重复使用同一类素材 |

一种常见但非固定的往返是：

`会说话的人物定题 -> 官方证明接管 -> 人物解释意义 -> 图片动效或机制动画讲明白 -> 人物换挡 -> Demo/真实现场落地 -> 人物收束`

停留多久由当前问题、证明或动作是否完成决定，不按固定秒数切镜。有效变化是叙事任务或可见状态发生变化，不是同一张卡换了字幕、裁切或入场动画。

## Beat Contract

声明本风格的 `material-beat-map.md` 在 `screen-owner-v1` 字段之外增加：

- `Presentation mode`：从本文件允许值中选择。
- `Takeover`：`full`、`dominant` 或 `bridge`。人物、证据、解释和场景正常应为 `full/dominant`；`support-card` 只能是 `bridge`。
- `Provenance`：`first-party`、`real-world`、`generated`、`internal-animation` 或 `n/a`。
- `Material`：写具体资产、路径或已登记的稳定资产 ID；动态数字人应能看出它是视频资产。
- `Motion action`：写可见动作和状态变化。`kinetic-image` 不能只写 fade/fly-in/scale。

已有的 `owner / purpose / handoff_reason / return_to_person / evidence_source / motion_action` 继续生效。不要另建一份平行镜头表。

## Assembly 规则

- 数字人出场使用会说话的视频，项目旁白仍是唯一声音主轨；不得把母图或静态截图放在成片里冒充说话。
- 人物拍点先让人物真正拥有画面，再从预留空间引入下一种素材；证明或动作已经能独立承担内容时，素材扩展并接管全屏。
- 图片动效以主体、空间和信息关系为中心设计推拉、视差、遮罩、局部揭示或状态变化，不把静态图塞进统一卡框。
- 官方页面和 Demo 保留来源辨识度，但要通过裁切、放大、光标路径或重点标记让观众看懂，不裸铺一个看不清的整页。
- 真实素材和 AIGC 素材必须有不同职责。真实素材负责现实与证明；AIGC 负责演绎和不可见部分，并在项目素材记录中保留生成来源。
- 复杂证据、机制或真实场景结束后，遇到新的问题、反转、价值判断、情绪抬升或结论，应让人物重新接管，而不是再接一张总结卡。

## Anti-patterns

- 动态数字人只在开头出现一次，后面长期无人重新锚定复杂信息。
- 数字人是静态照片、伪视频或无口型母图。
- 人物长期挂角，旁边从头到尾换 PPT。
- 连续 `support-card`、每句话一张卡、五栏清单和十二层列表成为主要镜头。
- 同一张素材换裁切、标题和局部动画后被计算成多个不同场景。
- AIGC 生成“官方页面”、数据截图或采访画面承担事实证明。
- 有真实 Demo 或真实现场可用，却用抽象图标、漏斗、脑形符号代替。
- 图片只做轻微缩放，仍像贴在幻灯片里的插图。
- 为了保留人物，把本应全屏的证据、操作或现场缩成不可读的小窗。

## QA 判断

接触表和正常速度播放必须回答：

1. 人物是否真正在说话，并在关键判断处多次重新获得主画面？
2. 观众能否分辨什么时候在看证明、什么时候在看解释、什么时候看真实行动？
3. 官方材料、Demo、实拍、图片动效和 AIGC 是否各司其职，而不是都被包成同一种卡片？
4. 连续复杂材料后是否有人的判断或新的现实动作重新定向？
5. 去掉字幕后，镜头本身是否仍在推进内容？

如果答案主要依赖“卡片在动”，即使技术检查通过，也要退回 Material 或 Assembly。

## 已验证正例

- 外部来源正例：所长林超《超指数分化世界》。全片时间序列核验显示，真人频繁承担提问、判断、转折、情绪抬升和结论；公式与概念按口播逐步出现，真实事件素材负责落地，生成/动画场景负责“平行世界”等不可直接拍摄的抽象概念，复杂材料结束后人物按语义回场。其发光圆角容器、科技皮肤和字体属于不可照抄的视觉皮肤；部分来源标注与小字可读性也不构成本项目降低证据 QA 的理由。

- DeepSeek 项目 v20/v28：动态数字人反复负责钩子、问题、边界、判断、情绪抬升和结尾；官方页面与 Demo 证明，办公室、工厂、仓库和数据中心把观点落到现实；人物在复杂材料后回场。v18 的“人物只开头一次、其余由板式画面承担”是反例。
- 机器人进厂项目 v12：真实产线承担主体，数字人只负责抛题、换挡和判断，动效强调结论；人工复核确认不再像 PPT。素材类型仍略有重复，说明“真实素材”也需要场景多样性。

这些案例只证明镜头语法有效，不意味着以后复制它们的画面皮肤、固定出场次数或切镜秒数。
